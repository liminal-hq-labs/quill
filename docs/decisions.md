# Decisions

Each decision is numbered and stays here even when superseded, with a note on what replaced it. Open questions move here once they are answered. Rows marked **Assumed** were made while the owner was away, from a brief that asked for reasonable assumptions; each stands until the owner confirms or changes it.

| # | Decision | Choice | Alternatives considered | Why |
|---|---|---|---|---|
| D1 | Home | A Liminal HQ Labs experiment in `liminal-hq-labs/quill`, public from the first commit | — | Try the idea in the open before it earns a place in Liminal HQ |
| D2 | Licence | `Apache-2.0 OR MIT` | — | House licence, compatible with both ecosystems |
| D3 | Dependency updates | No Dependabot configuration until the project opts in | — | Labs repositories stay quiet by default. See the [Labs charter](https://github.com/liminal-hq-labs/.github/blob/main/docs/labs-charter.md#dependabot-is-opt-in) |
| D4 | Win16 floor | Windows 3.1 in 386 Enhanced mode on a 386 or later; no Windows 3.0, Standard mode or real mode | Support Standard mode on a 286 | The Rust `code16` target uses 32-bit registers through prefixes, so it needs a 386, and Enhanced mode gives stable selectors for moveable memory and demand-loaded segments. Standard mode would double the testing for very few machines |
| D5 | Text engine | Quill's own document model, layout and GDI painting | The `EDIT` control; RichEdit | `EDIT` holds one font and 64 KB; RichEdit does not exist on Windows 3.1. An own engine is the only way to rich text, and it is also what lets DOS and the host share the editor |
| D6 | Text storage | A piece table over an original and an append-only add buffer, with the character format on each piece | Gap buffer; rope; a piece table with a separate run table | Opening a file is one read with no copying; undo never has to save deleted text; a gap buffer would move bytes across far memory on every jump. Formats on pieces make style runs fall out of the same structure, so one undo log covers both |
| D7 | Document memory | A `Store` of chunks of at most 32 KB with copy-in and copy-out, and `FarVec` on top; the core never holds a reference into document storage | References into far memory; huge (over 64 KB) blocks with `__AHINCR` arithmetic | Rust references are near pointers on Win16 and cannot point outside DGROUP. Small blocks never cross a selector boundary, so the core needs no huge-pointer logic, and the host meets the same chunk edges in tests |
| D8 | Core allocation | The portable crates are `no_std` without `alloc`; fixed-capacity tables in structs, `Store` for anything document-sized | `no_std` with `alloc` over a heap in DGROUP | A heap in a 64 KB segment would compete with the stack and Windows' local heap, and its failure would be a panic. Without `alloc`, every allocation is visible and fallible |
| D9 | Arithmetic | Integer and fixed-point layout; no floating point in any Quill crate, enforced by a link check for softfloat symbols | Softfloat `f32` | The Win16 target has no x87 and softfloat is large and slow on a 386. Integers make layout bit-identical on every platform, which the cross-platform tests rely on |
| D10 | Layout device | Lay out with the current printer's metrics (an information context), draw on screen at explicit character positions | Lay out per device (screen lines differ from printed lines); screen metrics only | What is on the screen is what prints, page numbers included, and print preview becomes cheap. Screen text spacing at 96 dpi can look a touch uneven, which Word for Windows also accepted |
| D11 | Character set | Windows ANSI (code page 1252), one byte per character, in every build | UTF-8; UCS-2 | Windows 3.1 and 9x GDI and file APIs are ANSI; one byte per character keeps far-memory copies and widths simple. RTF's `\u` maps to ANSI on read |
| D12 | Native format | A RIFF file, form type `QLD1`, with chunks per table and per story | RTF as the native format; Write's `.WRI`; a flat binary | RIFF is a Windows 3.1 container (multimedia used it), skips unknown chunks for forward compatibility, and loads without parsing. RTF stays the interchange format |
| D13 | RTF scope | Read broadly and skip safely; write a small canonical subset with fallbacks for older readers | Write everything Word 97 writes; read only what Quill writes | Documents come from many writers, so reading must be forgiving; a canonical writer is testable and round-trips |
| D14 | Code beyond 64 KB on Win16 | Several code segments; the packer finds cross-segment near calls from relocations kept with `--emit-relocs` and sends each through a veneer with a shadow return stack; function pointers go through an indirect-call table at the same offset in every segment | A code diet to fit one segment; DLLs per subsystem; LLVM far-call support; an overlay manager | LLVM cannot emit far calls for `code16`; Win16 DLLs have their own data segment with SS ≠ DS, which breaks the DS = SS assumption Rust code relies on; a code diet cannot fit a word processor with pictures and spelling. Veneers need no compiler change |
| D15 | Segment assignment | By mangled Rust path globs in `segments.toml`, generating the linker script; segment 2 stays DGROUP, code is 1 and 3 upward | By object file; by crate only | Under LTO everything is one object file, but function sections keep their mangled names, so paths still identify modules. Keeping DGROUP as segment 2 leaves the spike's packer conventions intact |
| D16 | Window model | One document per window (SDI), multiple instances allowed | MDI | Write and Notepad are SDI; MDI costs code and DGROUP and complicates the frame for little gain on a 640 × 480 screen |
| D17 | Menus and keys | Write 3.1's menu tree (File, Edit, Find, Character, Paragraph, Document, Help) with an Insert menu, CUA accelerators, Word for Windows 2.0 keys for formatting, and Ctrl+N, O, S and P | Write's keys only; Word 2's tree | Period users know Write's tree; CUA keys are what the Windows 3.1 guidelines prescribe; Ctrl+O and Ctrl+S cost nothing and today's users expect them |
| D18 | Standard dialogs | `COMMDLG.DLL` (Windows 3.1) and `COMDLG32.DLL` (Windows 9x) for open, save, font, colour, find, replace and print | Quill's own dialogs | They ship with Windows 3.1, behave as users expect, and save code and DGROUP |
| D19 | Panics | `panic = "abort"`; clippy denies unwrap, expect, panic, indexing and unchecked arithmetic in portable crates; the handler tries an emergency save; builds report panic sites | Catching unwinds | There is no unwinder on these targets, and a crash that loses the document is the worst outcome |
| D20 | Host reference | `quill-render` with `GridMeasure`, `DeskMeasure`, width tables captured from real Windows 3.11 (`CapturedMeasure`) and Liberation fonts (`LiberationMeasure`) | Test only in emulators | Layout bugs are found and seen on Linux in seconds; captured widths make the host lay out exactly as Windows does |
| D21 | Windows images in testing | The Windows 3.11 tree and the Windows ME VM are used locally only; CI runs Wine and DOSBox with freely redistributable parts | Put a Windows image in CI | Windows is not redistributable, and the repository is public |
| D22 | Print preview | In v1 | Later | With printer-metric layout (D10), preview is the same layout drawn smaller |
| D23 | Resource source | One JSON description (`quill.json`) with standard `.ico`, `.cur` and `.bmp` files, and generated Rust IDs | `.rc` files | The spike's packer already reads JSON; one source feeds the NE table, the Win32 `.res` and the DOS menu tree, and IDs cannot drift |
| D24 | Settings | `QUILL.INI` through the private profile APIs (Windows) and the same format beside the program (DOS) | `WIN.INI`; `REG.DAT` or the registry | Period-correct, removable with one file, shared by the two Windows builds |
| D25 | Undo | A bounded ring of inverse edits in far memory, grouped into labelled steps | Snapshots | Inverse edits are small because the piece table never loses bytes |
| D26 | Clipboard formats | Registered `Rich Text Format`, `CF_DIB` for a lone picture, and `CF_TEXT` | A private Quill format | RTF is what other word processors read; a private format would only help Quill-to-Quill pastes, which RTF already covers |
| D27 | Toolchain source | Copy the Win16 spike and Desk's DOS foundation with `PROVENANCE.md` files now; move to the `rust-win16` and `rust-win9x` templates when they exist | Depend on unpublished repositories by git | House rules allow copies with provenance, the builds stay reproducible, and the templates can be extracted from what Quill proves |
| D28 | Installer | Liminal Installer projects in `installer/` | A hand-written `SETUP.EXE` | Quill is the installer's best test case on Windows 3.1 and DOS, and the two projects share the toolchain |
| D29 | A Win32 build | A native Win32 build (`QUILL32.EXE`) for Windows 95, 98 and ME, alongside Win16 | Win16 only, running on 9x; Win32s on 3.1 | On Windows 9x a native build gets long file names, flat memory and a 32-bit look, and it costs only a thin layer because the core is shared. The Win16 build still runs on 9x as a bonus |
| D30 | Crate split | Portable crates (`quill-core`, `quill-formats`, `quill-image`, `quill-inflate`, `quill-spell`, `quill-app`, `quill-grid`) and one crate per platform (`quill-win16`, `quill-win9x`, `quill-dos`), each platform in its own workspace | One crate with `cfg` per platform | Separate crates keep platform code out of the portable crates by construction; separate workspaces let each platform pin its own toolchain and target, as Desk and the Liminal Installer do |
| D31 | Shared painting | The page, ruler, toolbar and status bar are painted once against a `Surface` trait, used through generics | Paint separately per platform; `dyn Surface` | Three GDI-like surfaces (Win16, Win32, DOS graphics) and a PNG canvas share one painter; generics avoid function pointers, which are awkward across Win16 code segments |
| D32 | Agreement across builds | Identical document limits and byte-identical saves in every build | Let each build use what it can (a bigger limit on Win32) | A document must open everywhere it was written; checked by saving the same scripted document on each build |
| D33 | Win32 CPU floor | Pentium (i586) without MMX or SSE; build `core` for it (or use `i586-pc-windows-msvc`) and scan the executable for newer instructions | i686 with the prebuilt `core`; a 486 floor | The prebuilt `core` for `i686-pc-windows-msvc` assumes SSE2 and would fault on Pentium-era machines; Windows 95 on a 486 has the Win16 build |
| D34 | Where Windows UI is built first | The Win32 build, on the Windows ME VM and Wine, then ported to Win16 | Win16 first | Win32 has none of the 64 KB constraints, so menus, dialogs, GDI painting and printing can be got right first; the Win16 port then has only Win16's problems |
| D35 | Win32 resources | Quill's own `.res` writer from `quill.json`, linked by `lld-link` | `llvm-rc` and `llvm-cvtres`; `windres` | The `.res` format is simple, one writer keeps NE and PE resources from drifting, and nothing needs Windows SDK headers. `llvm-rc` stays as a cross-check |
| D36 | DOS foundation | Desk's Rust-on-DOS `dos/` (target, linker script, runtime, go32 packer, DOSBox harness), copied with provenance, as the Liminal Installer did | DJGPP and C; a real-mode build | It already runs Rust on DOS with no C compiler, under a DPMI host that gives flat memory; the installer's copy shows the pattern works |
| D37 | Reference platform for editing behaviour | The host tests are the ground truth; DOS text mode is the first real-machine platform and the reference for editing behaviour (keys, selection, undo, files), compared exactly with host goldens; Win32 is the reference for GDI and dialogs; Win16 is validated against both | Win16 as the reference | DOS text mode is the quickest to run headless and its screens diff to the character, so editing bugs show up there before the hard Win16 work. It cannot check fonts or GDI, so it is not the reference for those |
| D38 | Styles in DOS text mode | Attributes for bold, italic, underline, strikethrough and their combinations; fonts, sizes and colours kept and named in the status line; a 10-pitch typewriter layout | Hide unsupported formats; drop them | Nothing is lost on a round trip, and the screen still shows which words are emphasized, as WordPerfect 5.1 did |
| D39 | DOS graphics fonts | Desk's outline faces rendered offline into bitmap strikes (`QUILL.FNT`) with width tables for the host | Rasterize outlines on DOS; Desk's four bitmap UI faces only | Offline strikes keep the DOS program small and fast; the UI faces have no serif or size range for documents |
| D40 | Order of work | Host core and reference renderer, then DOS text mode, then Win32, then Win16, with a Win16 toolchain track running in parallel from the start | Win16 first | Each step proves the core on a cheaper platform before the most constrained one, while the parallel track keeps Win16's unknowns from arriving late |
| D41 | Headers and footers | **Assumed.** In v1: one header and one footer, optionally a different first page, rich text, four fields; edited in a Write-style header view with a small dialog | A Word-style page layout view; a plain dialog with one line of text | The Write view is period-correct, reuses the editing view, and needs no page-layout editing mode |
| D42 | Stories and objects | **Assumed.** A document is up to five stories sharing tables and undo; pictures and fields are inline objects, one `0x01` character each | Pictures as floating frames; fields as text | Inline objects need nothing new from caret, selection, undo or RTF; floating frames would need wrap-around layout |
| D43 | Picture formats | **Assumed.** BMP (1, 4, 8, 24 bit) and PNG in v1; JPEG later; original bytes kept, display DIBs decoded by rows at the shown size and the display's depth, dropped under memory pressure; banded printing; a placeholder when it cannot fit | Keep decoded full-colour images; convert on insert and drop the original; JPEG in v1 | Decoding by rows is the only way a 4 MB machine shows a large picture; keeping the original means printing and saving lose nothing. JPEG needs a decoder that does not fit the budgets yet |
| D44 | Inflate | **Assumed.** `quill-inflate`: a streaming raw-deflate decoder with a 32 KB ring window, grown from Lt. Fizz 2's `fizz-pack` decoder (`~/source/experiments/fizz-2/crates/fizz-pack/src/inflate.rs`, `no_std`, no `alloc`, no `unsafe`) and copied with provenance | `miniz_oxide`; the Liminal Installer's inflater | Fizz's decoder is already small (about 2.3 KB at `opt-level = "z"`) and allocation-free, but writes into one whole-output buffer; PNG and chunked packs need a window instead, which is a contained change |
| D45 | Pictures in RTF | **Assumed.** Read `\dibitmap`, `\wbitmap` and `\pngblip`; write PNG pictures inside `\*\shppict` with a `\nonshppict` `\dibitmap0` copy, and BMP pictures as `\dibitmap0` | Write only `\pngblip`; write metafiles | Word 97 and later read `\shppict`; WordPad and older readers read the fallback. Doubling the picture in the file is the price of being readable everywhere |
| D46 | The v1.1 features | **Assumed.** Numbered and multi-level lists, tab stops with leaders, text colour, strikethrough, superscript and subscript, overtype and drag and drop move into v1; zoom is a stretch goal | Keep them in v1.1 | The owner asked for them in v1. Zoom is cheap with printer-metric layout but not essential, so it is first in the cut order |
| D47 | Lists | **Assumed.** A paragraph names a list definition and level; numbers are computed, not stored; RTF writes both `\listtable` and the Word 6 `\pn` form | Store numbers; write one RTF form | Computed numbers cannot go stale; two RTF forms keep Word 97 and older readers happy |
| D48 | Tab stops | **Assumed.** Interned tab sets of up to 16 stops, referenced from paragraph formats | Tab stops inside each paragraph format | Most paragraphs share a tab set; interning keeps paragraph formats fixed-size and small |
| D49 | Spelling | **Assumed.** SCOWL size 50 with VarCon variants (Canadian English default, American and British), a 4-byte-edge DAWG in 32 KB pages with a four-page cache, a plain-text user dictionary, suggestions within two edits under a time budget; as-you-type off by default on Win16 | Hunspell dictionaries and affix rules; a hash of words; a Bloom filter | SCOWL has Canadian English and a permissive licence with attribution; a DAWG is compact, needs no decompression to search, and pages fit far memory. Hunspell's affix engine is too big for Win16. A Bloom filter cannot suggest |
| D50 | Help compiler | **Assumed.** Quill's own WinHelp 3.1 compiler in Rust (`quill-help`, `hlpc`) and reader (`hlpdump`), implemented from Manfred Winterhoff's `helpfile.txt` and Pete Davis and Mike Wallace's *Windows Undocumented File Formats*, verified in the real `WINHELP.EXE`; no code from HelpDeco (GPL) or Wine (LGPL); written to move to a `rust-winhelp` repository | Ship no help (the earlier plan); plain text help; ask users for HC31 | Microsoft's Help Compiler is not redistributable, and a Windows 3.1 program without F1 feels unfinished. Reading the GPL and LGPL sources for behaviour is fine; copying them would bind the crate's licence |
| D51 | Help sources | **Assumed.** A small Markdown dialect (`.qhm`) plus `help.toml` | HC31's RTF with footnotes; HTML | Markdown is easy to write and diff, and the compiler owns the grammar; an RTF front end can be added later for existing help projects |
| D52 | Help on DOS | **Assumed.** `hlpc` also writes `QUILL.HLX`, shown by a help viewer in `quill-grid` | No help on DOS; a text file | One source, the same topics on every platform |
| D53 | Format versions | **Assumed.** `.QLD` 1.0 includes every v1 chunk from the start | Ship 1.0 for the old scope and 1.1 for the new | Nothing has shipped, so there is no older reader to stay compatible with |
| D54 | Cut order | **Assumed.** If time runs out, cut in this order: zoom, DOS graphics mode, PostScript printing on DOS, check-as-you-type on Win16, multi-level lists (keep one level), drag and drop, two-page preview, `.CNT` and phrase compression in the help compiler, PNG on Win16 (keep BMP) | Cut by platform | The order drops what users miss least first and keeps every platform shipping |
| D55 | Insert menu | **Assumed.** Add an Insert menu (Page Break, Picture, fields) to Write's tree | Put them under Edit, as Write did with pictures | Fields need a home, and Word for Windows 2.0 already had an Insert menu, so it stays period-correct |
| D56 | Help in v1 | **Assumed.** Supersedes the earlier non-goal of shipping no help file | — | D50 removes the reason for the non-goal |
| D57 | Release disks | **Assumed.** After v1, 1.44 MB floppy images: one per target operating system (DOS, Windows 3.1, Windows 95), each complete with its installer, and an all-in-one disk only if everything fits; never one platform split across two disks. Files travel in `.QPK` packs (a Quill variant of Lt. Fizz 2's `.FAP`, `~/source/experiments/fizz-2/docs/FAP.md`) with chunked deflate and a `no_std` unpacker in `quill-pack` that the installers share. Budgets in [roadmap.md](roadmap.md#release-disks) | One disk set across all platforms; ZIP files; the installer's own payload format only | A disk per operating system is what a period buyer expected and lets each fit with room; chunked deflate unpacks in 32 KB on Win16, and sharing the reader means one unpacker to test |
| D58 | Paragraph formats | **Assumed.** A paragraph's format index rides on the pieces that hold its paragraph mark (`0x0D`): each piece carries a character format and a paragraph format, and only the marks it holds use the second. Setting a paragraph format splits and sets pieces through the same code as a character format, and the one undo log covers both | A separate paragraph record list with start positions kept in step with every edit | Formats on pieces made undo of character formats free (D6); the same trick makes undo of paragraph formats free, and a paragraph's format cannot drift from its mark when text is inserted, deleted or undone. A merged paragraph takes the later mark's format, as Word does. The per-paragraph layout cache (top, line count) is still a separate structure, rebuilt from the text |
| D59 | `LIST` chunk id | **Assumed.** The SPEC names both the list definitions chunk and the story container `LIST`. A reader tells them apart by the first two bytes: a story container starts with the form type `STRY`, a definitions chunk with a count of at most 64 | Rename the definitions chunk | The SPEC was written that way and nothing has shipped; `STRY` as a count would be 21,587 lists, which the limits refuse, so the two cannot be confused. The SPEC records the rule |
| D60 | Lints and overflow | **Assumed.** The portable crates deny `unwrap`, `expect`, `panic`, `unreachable`, `todo` and indexing or slicing with clippy; `clippy::arithmetic_side_effects` is not denied yet, and release builds keep `overflow-checks` on so an overflow aborts instead of wrapping | Deny arithmetic side effects now | Layout and the piece table are full of position arithmetic that property tests exercise; checked arithmetic everywhere would bury the code before the edit paths exist. Revisit at M2, when the editing code is complete |
| D61 | Page images before fonts | **Assumed.** Until a font renderer exists (M10), `quill-render`'s PNG is a page map: one block per character cell with the text area's corners, 1-bit, stored deflate | Draw glyphs from a bitmap font now | A page map shows where lines and tabs fall, which is all `GridMeasure` knows, and needs no font file. Glyph pages arrive with `DeskMeasure` and `LiberationMeasure` |
| D62 | Layout in M0 | **Assumed.** Layout uses the default tab stops (every half inch) and one line height per font until the Tabs dialog and list work land; the history drops everything older when its chunks are full | Implement tab sets and a bounded ring first | Both are replaced by the full versions in M2; the golden dumps will change then, in a reviewed diff |
| D63 | Win16 register rule | **Assumed.** Every import stub and exported-procedure wrapper saves and restores the full 32-bit EBX, ESI, EDI and EBP, and no Rust code or helper keeps a value in FS or GS across a call | Save only what the probe showed lost in one case | T1 showed that a task switch hands one task the other's high halves and that API calls zero FS and GS (see `docs/progress.md`); saving all four registers in the stubs is the one rule that covers every yielding call |
| D64 | Jump tables on Win16 | **Assumed.** Jump tables are disabled for the Win16 target (`-min-jump-table-entries=1000`) until the fault found in T1 is explained | Leave them on and avoid dense `match`es by hand | One dense `match` crashed the probe; nobody can audit every `match` in a word processor |
| D65 | Where the shared pieces live | **Assumed.** `GridMeasure` is in `quill-grid` and the heap-backed store is `quill-heap` (`HeapStore`, re-exported by `quill-host` as `HostStore`); the key-script player and in-memory files stay in `quill-host` | `GridMeasure` and `HostStore` in `quill-host`, as the architecture said | The DOS program needs both and cannot depend on a `std` crate; Win32 will use `quill-heap` too |
| D66 | Save in M1 | **Assumed.** `File > Save` writes the file directly; the temporary file and replace the SPEC asks for arrive with the Win32 build's file layer (M4) | Add INT 21h rename to the runtime now | M1 is about editing; the safe save needs the same rename on three platforms and belongs with the common file layer. A failed save can leave a damaged file until then |
| D67 | Driving DOS in tests | **Assumed.** DOSBox's `AUTOTYPE` presses one key at a time, so end-to-end scripts reach commands through F10 and the menus, and Ctrl accelerators are tested on the host; the key list must have single spaces (runs of spaces make it stop early) | Hold Ctrl through DOSBox key mapping | AUTOTYPE has no chords; the host script player covers the accelerators, and the same `App` code handles both |
| D68 | F8 extends the selection | **Assumed.** F8 toggles extend mode in DOS text mode, in addition to Shift with movement; the SPEC records it | Test selection on the host only | DOSBox's AUTOTYPE cannot hold Shift, and the end-to-end run must show selection and formatting on the real DOS build |
| D69 | Tab layout | **Assumed.** Centre, right and decimal stops hold the following text back by looking ahead to the next tab (at most 200 characters); a segment wider than the room advances nothing; leaders are drawn by the painter, as repeated characters | Place the segment after the fact | Looking ahead keeps line breaking single-pass and the same on the host and on DOS; the host's layout dump and the grid painter share `tab_advance` |
| D70 | Banner palette | **Assumed.** Ink blue (`#0a1230` to `#16275a`, darker in dark mode) and parchment (`#fff4d6` to `#e9dcb0`) with one amber accent (`#f0a830`: the nib, the status chip, the title's last stop, one coloured word); the three operating-system windows keep muted period colours; README badges use the amber and the ink | The template's lime and rose; Windows 3.1's own teal | A palette of its own, not shared with other Liminal HQ repositories, that reads as paper and ink and lets the three windows be the only strong blues and greys |
| D71 | Pack format | **Assumed.** Quill keeps its own `.QPK` (D57) for release disks, and `.QPK` is provisional: it is expected to be replaced by `.LPK`, the shared Liminal Pack format of liminal-installer's `li-lpk`, in a separate change when that crate is ready. File reading goes through the `Files` trait in `quill-app` and dictionary and help paging will go through a `PageSource` trait, so a pack reader can back either without touching the editor | Wait for `li-lpk`; build `.QPK` as the only format | Release disks are late in the order, so nothing waits; the traits make the flip small |
| D72 | First Win32 build | **Assumed.** `QUILL32.EXE` first draws the text-mode grid in a Win32 window (the OEM fixed font, 80 by 25 cells) and takes keys from `WM_KEYDOWN` and `WM_CHAR`, so it runs the same `quill-app` and can be checked screen for screen against the host; the GDI page with real fonts, native menus, common dialogs and printing (M3's acceptance and M4) come after | Start with GDI | It shows the core and the Win32 toolchain working on Wine and Windows ME at once, and gives the golden comparison a third platform. M3 is therefore **not** done: the page is not drawn with GDI fonts and nothing is matched with `CapturedMeasure` |
| D73 | Screen metrics | **Assumed.** The host's `CapturedMeasure` reads a table that `QUILL32.EXE /CAPTURE` writes on the machine whose fonts it describes (`tests/metrics/screen96-windows-me.txt` is from the Windows ME VM: three faces, ten sizes, four styles, widths and vertical metrics at 96 dpi). The golden `tests/golden/layout/letter.windows-me.txt` is what `/LINES` wrote on the VM, so the host test shows it breaks the same lines as Windows ME | A Win16 capture program on Windows 3.11 (the plan's first idea) | Windows ME has the same TrueType fonts and the Win32 build already runs there; the Windows 3.11 table is still to be captured when the Win16 build exists |
| D74 | Dialogs on the GDI page | **Assumed.** The GDI view uses the native menu bar (loaded from the `.res`, built from the app's own tree) and the common Open and Save As dialogs; Find, Replace, Fonts, Tabs and the save prompt stay the app's own text-cell dialogs, drawn over the page | Native dialogs for all | One dialog implementation shared with DOS; native Find, Fonts and Tabs dialogs need dialog templates in the `.res` and callbacks, which come with print and the colour dialog |
| D75 | App icon | **Assumed.** Concept 4, a Q whose tail is a nib: a thick amber ring on an ink-blue rounded square, a parchment nib crossing it at the lower right, in the D70 palette. `assets/icon/quill.svg` is the master; `quill-small.svg` is a bolder drawing (a thicker ring, a plain nib, no glow) used at 32 px and below | The other five concepts: a signature, a feather, a folio page, a nib on a drop of ink, a window | It still reads as a Q at 16 px, where a feather or a page is a blur; the nib says "writing" without a feather's cliché; and it needs only the palette's three colours |
| D76 | Icon colour depths | **Assumed.** `tools/make_icons.py` writes every icon from the SVGs, reproducibly. `QUILL.ICO` holds 16, 32 and 48 px at 4, 8, 24 and 32 bits and a PNG-compressed 256 px: the 4-bit images use the sixteen standard Windows colours (flat drawing, the 16 px one by hand), the 8-bit ones the 20 static system colours at indices 0 to 9 and 246 to 255 around 236 median-cut colours, the 24-bit ones a 1-bit mask, the 32-bit ones alpha with the mask set where alpha is 0 (Windows 98 and Me ignore alpha). The Windows 3.x icon is 32 px at 16 colours (`QUILL31.ICO`, the default); `QUILL31X.ICO`, 32 px at 256 colours, is an option. Windows 3.11 under DOSBox-X loads both in 16-colour, 256-colour and 64K-colour video; a 256-colour display draws it with the 20 static colours only (the icon is not realized into the palette), so it looks no better than the 16-colour one there, and only a high-colour driver shows its gradients. `win16/tools/ne_pack.py` takes `icons` in the resources JSON and writes the `RT_GROUP_ICON` and `RT_ICON` resources from an `.ico`; `win9x/tools/res_pack.py` does the same for the Win32 `.res`, from `QUILL.ICO` | One 32 px 16-colour icon everywhere; only 24-bit and alpha; GIMP-made files by hand | Windows picks the size and depth the display wants, so every machine from a 16-colour VGA to a modern desktop shows an image made for it, and the files rebuild from the SVGs when the art changes.
